## Repository identity and working boundaries

- Native Kotlin Android endless runner, package `com.anurag9000.forestrun`, fixed landscape, min API 24, compile/target API 36, Java/Kotlin 17 bytecode.
- Main gameplay loop: Willow/Home → five biomes → nineteen encounter families → Seeds and Bloom → Rest → persistent Garden, relationships, wardrobe and Journal → next run.
- `main` is documented as the sole development branch; commits are direct and history-preserving.
- The tree was `main...origin/main` when this map was started. `ISSUE_NOTES.md` was already untracked and is included in the doc inventory without modification. No `AGENTS.md` was found under the workspace parent.
- Documentation inventory at mapping time: 199 pre-existing authored Markdown-family files (including release copy and `ISSUE_NOTES.md`), about 19,031 lines / 989 KB; this map is the 200th. Generated Android build reports, R8 mapping, `.gradle` and IDE state are excluded. Store-facing `.txt` projections are covered by the store-listing/evidence docs; `docs/audits/` holds the dated change/evidence trail.
- Do not interpret the large root-level `Final_Assets (2)/` as runtime assets: it is source/reference creative material. Runtime assets and the provenance registry are distinct.

## Authority and status rules

1. **Current source owns runtime truth.** Current specs define intended contracts; regression tests and exact-head workflow evidence show what was exercised.
2. **A dated audit is historical.** It records the then-current finding, correction, and evidence limit. Later audits may supersede or reopen earlier conclusions. In particular, 2026-09-27 explicitly corrected earlier overclaims about Eagle staging and spawn fairness.
3. **Source completeness is not release acceptance.** README, CHANGELOG, release specs and audits consistently distinguish implemented source from physical, human, legal, store, signing, privacy, vulnerability-reporting and accountable approval gates.
4. **Validators validate evidence structure and bindings; they do not create truth.** A passing schema/hash check does not prove that a human statement is true, art is good/licensed, a device behaved well, or Play delivery happened.
5. **Keep independent durability domains independent.** Application persistence has explicit mutation boundaries, but there is no claim of one transaction across preferences, ghost files, story, relationships and presentation.
6. **Prefer projection over duplicate authority.** The Forest Journal reads existing progression facts; don't add an achievement/save namespace when history already owns the fact.
7. **Fail closed for ambiguity, malformed input, stale candidate evidence, aliasing, and unresolved recovery.** Preserve corrupt evidence until a confirmed domain-specific action.
8. **No retained trainable ML surface exists.** `run_all_training.py`, `training_control/` and three audit workflows are applicability/fail-closed scaffolding; ML training, datasets, GPU parity and model matrices are N/A, not missing Forest Run product features.

## Product/runtime ownership map

```text
MainActivity
 ├─ GameView / GameThread (SurfaceView simulation, render, lifecycle, touch, semantic access)
 │   ├─ GameStateManager + RunSessionTransitionCoordinator/Planner (run state and transition effects)
 │   ├─ InputHandler + Player (gesture arbitration, physics, animation and stance geometry)
 │   ├─ BiomeManager + EncounterDirector + EncounterFamilyCatalogue
 │   │   └─ EntityManager / EntityFactory → 19 concrete flora/tree/bird/animal families
 │   ├─ Collision arbitration → one terminal encounter outcome → outcome-specific coordinators/effects
 │   ├─ Bloom/Seed/SeedOrb, parallax, particles, audio, haptics and dialogue presentation
 │   ├─ Menu / HUD / Rest / Garden Canvas UI + native ForestJournalActivity
 │   └─ semantic virtual-node provider, action router, safe-content/touch transform, feedback settings
 ├─ ApplicationPersistenceFacade → SaveManager and domain-specific managers/stores
 │   ├─ Garden purchase + Seed award shared mutation lock
 │   ├─ relationship, encounter memory, forest mood, return moments and story pages
 │   ├─ non-ghost run-outcome journal + atomic summary/route snapshot
 │   └─ ghost recorder/player + namespace-bound promotion receipt/manifest/artifact recovery
 └─ RecoveryEvidenceDialogCoordinator (privacy-safe, confirmed domain-specific recovery actions)
```

Key behavioral contracts:

- Quick tap / hold / early release / downward swipe are mutually arbitrated and cancellation-safe. Stance updates must match drawn Player geometry and accessibility actions must enter the same live ownership rules.
- Bloom is 8 Seeds and lasts 6 seconds; it does not freeze locomotion, stack/restart its timer, or double-count ordinary encounter/Orb rewards. Visual admission sanitizes malformed strength independently of game state.
- Collision severity is HIT > STUMBLE > MERCY. Collision probes must be pure; MERCY is provisional until full safe passage, and must not mask later same-encounter HIT/STUMBLE. Swept component contact handles fast/narrow hazards.
- Random encounter admission uses action feasibility and the fastest approach over the complete reaction window; an origin gap or deterministic script alone is not a physical-fairness certificate.
- Terminal outcomes claim a per-run token. Non-ghost progress is journaled before/after; summary and route count commit atomically. Ghost promotion has its own versioned receipt/manifest and distance-bound identity, worker sequencing and per-save-namespace scheduling.
- Garden spending and run Seed awards serialize on one lock. Permanent counters/unlocks use bounded/monotonic or union semantics where documented. Story, return moment and mood transitions have explicit ownership and timing.
- Journal is observational. Reading it must not refresh relationships/costumes, unlock story, mutate counters, consume return moments, or purchase anything.
- Accessibility uses stable semantic IDs, validated direct actions, live availability invalidation, touch-aligned geometry, native Journal controls, reduced-motion/audio/haptic preferences, and coalesced announcements. Source implementation is distinct from TalkBack/Switch Access acceptance.

## Evidence chain and dependencies

```text
exact clean main SHA
  → host/release + connected Android validation
  → build/sign one artifact; verify bundle and certificate
  → Play internal-track delivery evidence
  → physical device acceptance (five classes, seven scenario groups, thresholds)
  → installed identity matrix (each actual session/device)
  → detailed human acceptance
  → governance evidence (legal/security/privacy/store/provenance/presentation)
  → canonical listing parity + candidate-bound metadata, screenshots and graphics
  → stable evidence index (all material files, immutable digest set)
  → independent index verification + final readiness cross-validation
  → independent accountable release decision and exact candidate tag
```

Any candidate/source/artifact/store/evidence change invalidates relevant downstream evidence. Upload certificate and Play app-signing certificate are distinct. Store installer attribution does not alone prove the Play track. Readiness verifies that all layers refer to the same candidate, bundle and cert identities and that exact accepted manifests are the indexed files.
